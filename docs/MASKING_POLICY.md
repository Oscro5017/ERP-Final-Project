# นโยบายการปิดบังข้อมูล (Masking Policy)

> แหล่งอ้างอิงเดียวสำหรับ "ฟิลด์ไหนปิด/เปิด" ของ ERP บ้านผักสดฟาร์ม
> ถ้า prompt, blueprint หรือโค้ดขัดกับตารางนี้ ให้ถือตารางนี้เป็นหลัก แล้วแก้อีกฝั่งให้ตรง
> **สถานะปัจจุบัน: ทีมตัดสินใจแล้ว แต่เจ้าของฟาร์มยังไม่ยืนยันรายละเอียดบางส่วน** (เจ้าของยังไม่มั่นใจว่าควรปิดแค่ไหน อาจปรับหลังคุยครั้งถัดไป — พัฒนาแบบหมุนรอบ)
> ปรับปรุงล่าสุด: 2026-11-01

## หลักการของรอบนี้

- **ปิด:** ข้อมูลเกี่ยวกับคน, ชื่อปุ๋ย/ยา/ปุ๋ยผสมที่ขาย, ข้อความอิสระ, และ **จำนวนเงินทุกชนิด**
- **เปิด:** ปริมาณและยอดคงเหลือ เพราะชื่อที่ปิดอยู่ปกป้องสูตรในระดับหนึ่งแล้ว และตัวเลขปริมาณเป็นหัวใจของสต็อกอัตโนมัติ (D4) ที่ต้องใช้ SQL
- เหตุผลที่ปิด "จำนวนเงินทุกชนิด" ไม่เลือกปิดบางตัว: กำไร = รายได้ − ต้นทุน ถ้าเปิดตัวใดตัวหนึ่ง ตัวที่ปิดไว้จะคำนวณย้อนได้

## สัญลักษณ์สถานะ

- ✔ **ข้อกำหนดเดิมจากเจ้าของ** (อยู่ใน `PROJECT_CONTEXT.md` หรือบอกตอนสัมภาษณ์)
- ◐ **ทีมตัดสินใจ** รอยืนยันรายละเอียดกับเจ้าของ
- ✖ **ยังไม่ตัดสินใจ** ต้องถามเจ้าของ

## กติกาการเปลี่ยนนโยบาย

1. **ทุกครั้งที่เปลี่ยน ต้อง** อัปเดตตารางนี้ (สถานะ + วันที่) แล้วแก้ prompt/blueprint ที่อ้างอิง
2. **ถามเจ้าของครั้งถัดไป:** แถว 11–12 (ปริมาณเปิดได้ไหม), แถว 16 (ชื่อเมล็ด), และแถว 13 ส่วนที่ไม่ใช่รายได้ (ต้นทุน/ค่าแรง) ให้ปิดตามหรือไม่
3. **ทุกการเปลี่ยนที่กระทบข้อมูลที่มีอยู่ต้องมี migration** ตามแบบ Phase 1d/1e: สำรองไฟล์ก่อนไปไว้นอก repo, ตรวจ round-trip ทุกแถว, ตัด/เพิ่มคอลัมน์, `vacuum`, `PRAGMA integrity_check`, รันซ้ำได้ — ทำได้ทั้งสองทิศ (เข้ารหัส ↔ ถอดรหัส)
4. สำรอง `ENCRYPTION_KEY` แยกจากฐานข้อมูลเสมอ และ key ใน production ต้องเป็นของเจ้าของ (ดู `PROJECT_CONTEXT.md`)

## กติกาการออกแบบ

- **จำนวนเงินทุกชนิดต้องคำนวณที่ backend หลังถอดรหัส** ผ่านชั้น service (เช่น `finance_service`) ห้ามใช้ SQL `SUM`/`GROUP BY` กับฟิลด์เงิน ข้อมูลฟาร์มขนาดนี้โหลดมาคำนวณใน Python ได้ แต่ **ต้องวัดบน Pi 4 (2GB) จริง** ก่อนเชื่อ หน้ารายงานหลายปีควรเก็บยอดสรุปรายเดือน (เข้ารหัส) เพื่อไม่ต้องถอดรหัสซ้ำ
- **ปริมาณและสต็อกใช้ SQL ได้** (plaintext) การตัดสต็อกอัตโนมัติใช้ตารางความเคลื่อนไหวเดียว
- **Developer view:** จำนวนเงินแสดงเป็นป้าย "ข้อมูลเข้ารหัส" และ aggregate แบบ masked (`MaskedAggregate`) ปริมาณและยอดคงเหลือแสดงตัวเลขจริง ชื่อลูกค้า/พื้นที่/ปุ๋ย เป็นป้ายเข้ารหัส กราฟหรือตารางตามลูกค้า/พื้นที่ใช้ป้าย "ลูกค้า #id (เข้ารหัส)" / "พื้นที่ (เข้ารหัส)"
- รูปแบบ response `is_masked` เหมือนเดิมทุก endpoint
- ห้ามใส่ข้อมูลกลุ่ม "ปิด" ลงใน log, ข้อความ error, toast, dialog, ข้อความของ Task อัตโนมัติ หรือชื่อไฟล์ export
- ห้ามเก็บตัวเลขเงินใน note หรือชื่อสินค้า (จะหลุดเป็น plaintext หรือข้ามการปิดบัง)

## ขอบเขตการป้องกัน (ต้องเขียนในเอกสารส่งงาน)

การปิดบังระดับฟิลด์กันการเห็นผ่านแอปและการเปิดไฟล์ฐานข้อมูลดูเท่านั้น ผู้ที่เข้าถึง shell ของเครื่องและอ่าน `ENCRYPTION_KEY` ได้ยังถอดรหัสได้ ช่วงพัฒนาให้ใช้ข้อมูลสมมติ ส่วน production บน Pi ให้ใช้ key ของเจ้าของ ปริมาณที่เปิดอยู่อาจใช้ประมาณรายได้คร่าวๆ ได้เมื่อรวมกับราคาตลาด
