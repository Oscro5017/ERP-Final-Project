# Front-end Blueprint: owner-mobile (ฝั่งเจ้าของฟาร์ม — มือถือ) [ฉบับปรับปรุง]

> **SCOPE**: `owner-mobile`  
> **เป้าหมาย**: ออกแบบและวางแผนโครงสร้าง UI ฝั่งเจ้าของฟาร์ม (Mobile-First) สำหรับระบบ ERP ฟาร์มไฮโดรโปนิกส์ (ERPOganicFarm) ให้ใช้งานง่าย เหมาะกับการบันทึกข้อมูลหน้าแปลงผ่านมือถือ และสอดคล้องกับ 4 โมดูลหลักของ ERP (สินค้า, คลัง, รับเข้า, ส่งออก) ตามนโยบายการปิดบังข้อมูล (Masking Policy) ล่าสุด

---

## 1. สรุปผู้บริหาร (Executive Summary)

- **ปัญหาหลักของระบบ As-Is**: หน้าจอเว็บเดิมออกแบบสำหรับเดสก์ท็อป ตารางล้นจอเมื่อเปิดบนมือถือ เมนูรก และฟังก์ชัน As-Is ส่วนใหญ่ยังเป็น mock ข้อมูล
- **โครงใหม่ใน 1 ภาพ**: 
  - **แถบเมนูล่างมือถือ (5 ช่องมาตรฐาน)**: `[ ภาพรวม ] [ ฟาร์ม ] [ รับเข้า/ส่งออก ] [ สินค้า & คลัง ] [ การเงิน ]`
  - **เมนูแถบบน / Drawer**: สภาพอากาศ (อากาศที่ฟาร์ม), คู่ค้า (ลูกค้า/ซัพพลายเออร์), ตั้งค่า
- **5 เรื่องที่ต้องตัดสินใจก่อนลงมือทำ**:
  1. การยืนยันสัญญารายปีและพื้นที่ส่งมอบในออเดอร์ส่งออก (Phase 2)
  2. การผูกสต็อกอัตโนมัติ (StockMovement) กับทุกกิจกรรมรับเข้า/ส่งออก/ให้ปุ๋ย (D4)
  3. รูปแบบการกรอกข้อมูลการเงิน/ค่าแรงในหน้ากิจกรรม (Task) แบบไม่บังคับ (D5)
  4. การใช้เว็บ PWA (Progressive Web App) เทียบกับการพัฒนาแอป Flutter แยกต่างหาก
  5. การจัดการข้อมูลลับตาม Masking Policy ล่าสุด (ปิดข้อมูลคน, ชื่อปุ๋ย/ยา/ปุ๋ยผสม, note, manual task title, และจำนวนเงินทั้งหมด)

## 2. ข้อขัดแย้งกับ developer-desktop (Conflicts Resolution)

| หัวข้อ / ส่วน | ที่ฉันเขียนรอบแรก | ที่ถูกต้อง / มาตรฐานร่วม | หลักฐานจากโค้ดจริง / Blueprint |
|---|---|---|---|
| รายชื่อ Route As-Is | ใช้ path สมมติ (`/dashboard`, `/crop-cycles`, etc.) และ `Login.jsx` เป็น route | 11 routes จริง: `/`, `/plots`, `/plots/:id`, `/activities`, `/harvest`, `/inventory`, `/sales`, `/costs`, `/reports`, `/users`, `/settings` (Login เป็น auth gate ใน `App.jsx`) | `src/App.jsx` บรรทัด 15–35 |
| สถานะ API ของ Inventory / Sales / Reports | ระบุว่า "มี API จริง / ผสม" | **Mock ทั้งหมด** (ยังไม่มี API จริงสำหรับสต็อก, ซัพพลายเออร์, ออเดอร์/ขาย, รายได้) | ตรวจสอบ `src/services/` และ `src/pages/` |

| ข้อมูลการเงิน / รายได้บน Dashboard | แสดงตัวเลขจริงตัวอย่าง (`฿251,500`) | ห้ามแสดงตัวเลขเงินที่ดูเหมือนจริง เนื่องจากไม่มี API รายได้ และจำนวนเงินจัดเป็นข้อมูลลับตามนโยบายใหม่ | `MASKING_POLICY.md` / ไม่มี API รายได้ |

### 3.2 ปัญหาการใช้งานบนมือถือ (Mobile Usability Issues)
- **Layout & Sidebar**: `DashboardLayout` ใช้ Sidebar แบบฟิกซ์ความกว้างบนเดสก์ท็อป ทำให้บนมือถือจอแคบ (< 400px) เนื้อหาถูกบีบอัดและตารางข้อมูลเกิด Horizontal Scroll
- **Touch Target**: ปุ่มกดใน `TaskWidget` และตาราง As-Is มีขนาดเล็กกว่า 44×44 px ทำให้ใช้งานยากเมื่อสวมถุงมือหรืออยู่กลางแจ้ง
- **Forms & Modals**: ฟอร์มเพิ่มข้อมูล As-Is เป็น Modal แบบเดสก์ท็อป ไม่รองรับ Bottom Sheet สำหรับมือถือ

## 4. ส่วน 2 — แผนที่เป้าหมาย (To-Be) รายหน้าสำหรับเจ้าของ (8 หน้าหลัก)

### 4.1 ภาพรวม (Dashboard) — Path: `/`
- **เป้าหมาย**: สรุปงานวันนี้ สภาพอากาศที่ฟาร์ม กราฟแสดงผลผลิตรายสัปดาห์ และรอบปลูก active ให้เจ้าของเห็นทันทีที่เปิดแอปเพื่อการตัดสินใจที่รวดเร็ว
- **Wireframe ASCII (Mobile)**:
  ```
  +----------------------------------+
  + 🌿 ERP Farm            [⚙️] [👤] +
  +----------------------------------+
  + [ อากาศที่ฟาร์ม ]                  +
  + 31.5°C | ☀️ แดดจัด | ความชื้น 65%   +
  +----------------------------------+
  + [ 📊 กราฟผลผลิตรายสัปดาห์ (กก.) ]   +
  +  [|||] [||||] [||||||] [||||]    +
  +  W1    W2     W3      W4         +
  +----------------------------------+
  + [ งานวันนี้ (2) ] [ รอบปลูก (3) ]   +
  + - ตรวจ EC/pH แปลง A1 [☑]        +
  +----------------------------------+
  ```
- **แหล่งข้อมูล**: ใช้ Mock ทั้งหมด (รอ Backend Phase 2)
- **การแสดงผล Owner vs Developer**: Owner เห็นสถานะงานจริง; Developer เห็นป้าย Masked สำหรับข้อมูลเงิน/ชื่อแปลงลับ
- **สถานะ UI / ขนาดงาน**: S (≤ ครึ่งวัน)

### 4.2 ฟาร์ม (Farm) — Paths: `/farm/cycles`, `/farm/cycles/:id`, `/farm/activities`
- **เป้าหมาย**: จัดการรอบปลูก, ดูรายละเอียดแปลง, และบันทึกกิจกรรมประจำวันพร้อมค่าใช้จ่ายไม่บังคับ (D5) และบันทึกปุ๋ย/ยา (D4)
- **Wireframe ASCII (Mobile)**:
  ```
  +----------------------------------+
  + [ รอบปลูก ] | [ กิจกรรม ]         +
  +----------------------------------+
  + 🔍 ค้นหารอบปลูก...                +
  +----------------------------------+
  + [ แปลง A1: ผักสลัด (Active) ]     +
  +   เริ่ม: 01/03/2026 | คาดเก็บ: 05/04 +
  +----------------------------------+
  + [ แปลง B1: เรดโอ๊ค (Harvested) ]  +
  +----------------------------------+
  +             [ + เพิ่มรอบปลูก ]     +
  +----------------------------------+
  ```
- **แหล่งข้อมูล**: Mock ทั้งหมด
- **ผลของ D4 & D5**: 
  - ฟอร์มบันทึกปุ๋ย/ยา: เลือกสินค้าจาก Catalog, แสดงยอดคงเหลือ, เตือนเมื่อไม่พอ, สร้างสินค้าใหม่ได้ทันที
  - ฟอร์มกิจกรรม: มีส่วน "ค่าใช้จ่ายของงานนี้ (ไม่บังคับ)" แบบพับเก็บได้ (ซ่อนชื่อคนงานและจำนวนเงินตามนโยบายใหม่)
- **ขนาดงาน**: M (1–2 วัน)

### 4.3 สภาพอากาศ (Weather) — Path: `/weather`
- **เป้าหมาย**: ตรวจสอบสภาพอากาศปัจจุบันที่ฟาร์ม, พยากรณ์ 7 วัน, และประวัติย้อนหลัง
- **แหล่งข้อมูล**: Mock ทั้งหมด
- **ขนาดงาน**: S (≤ ครึ่งวัน)

### 4.4 สินค้า & คลัง (Products & Inventory) — Path: `/products`
- **เป้าหมาย**: ตารางเดียวรวมสินค้าและยอดคงเหลือ พร้อมชิปตัวกรองประเภท และแผงรายละเอียด Movement (D4)
- **แหล่งข้อมูล**: Mock ทั้งหมด (ต้องสร้าง Backend ใน Phase 2)
- **ขนาดงาน**: L (> 2 วัน)

### 4.5 รับเข้า / ส่งออก (Inbound / Outbound) — Paths: `/trade/inbound`, `/trade/outbound`
- **เป้าหมาย**: บันทึกรับเข้าและส่งออกผลผลิต พร้อมตัด/เพิ่มสต็อกอัตโนมัติ (D4)
- **แหล่งข้อมูล**: Mock ทั้งหมด (ต้องสร้าง Backend ใน Phase 2)
- **ขนาดงาน**: L (> 2 วัน)

### 4.6 การเงิน (Finance) — Paths: `/finance`, `/finance/reports`
- **เป้าหมาย**: สรุปต้นทุน, รายได้, กำไร, และรายงานตามไตรมาส/ฤดูกาล (แสดงผลแบบ Masked สำหรับ Developer)
- **แหล่งข้อมูล**: Mock ทั้งหมด (ต้องสร้าง Backend ใน Phase 2)
- **ขนาดงาน**: L (> 2 วัน)

### 4.7 คู่ค้า (Partners: Customers & Suppliers) — Paths: `/partners/customers`, `/partners/suppliers`
- **เป้าหมาย**: จัดการซัพพลายเออร์และลูกค้า (ข้อมูลบุคคลและช่องทางติดต่อถูกปิดบังตาม D2/Masking Policy)
- **แหล่งข้อมูล**: Mock ทั้งหมด
- **ขนาดงาน**: M (1–2 วัน)

### 4.8 ตั้งค่า & โปรไฟล์ (Settings) — Paths: `/settings/profile`, `/settings/users`
- **เป้าหมาย**: จัดการโปรไฟล์ผู้ใช้และสิทธิ์ระบบ
- **แหล่งข้อมูล**: Mock ทั้งหมด
- **ขนาดงาน**: S (≤ ครึ่งวัน)

## 6. ส่วน 4 — Gap Analysis

| ข้อกำหนด / นโยบาย | โครงใหม่รองรับ? | สถานะ | สิ่งที่ต้องพัฒนาเพิ่ม |
|---|---|---|---|
| D1: เจ้าของใช้มือถือ (Mobile-first) | รองรับผ่าน Bottom Nav & Card layout | ครอบคลุม | ปรับขนาด Touch target และ Bottom sheets |
| D2: ปิดบังข้อมูลคนทั้งหมด | รองรับผ่าน Masking Policy & `is_masked` | ครอบคลุม | ตรวจสอบหน้าคู่ค้าและกิจกรรม |
| D3: ปิดบังชื่อปุ๋ย/ยา/ปุ๋ยผสม | รองรับผ่าน Product masking | ครอบคลุมบางส่วน | พัฒนาหน้าสินค้า & คลัง |

| D5: กิจกรรม + การเงินไม่บังคับ | รองรับผ่านฟอร์มพับได้ใน Task | ยังไม่มี (Phase 2) | เพิ่มฟิลด์ค่าใช้จ่ายใน Task form |

## 7. ส่วน 5 — Implementation Slices (`owner-mobile`)

1. **Slice 1 (S)**: โครงเมนูมาตรฐานและ Bottom Navigation Bar บนมือถือ พร้อมระบบ Responsive Shell
2. **Slice 2 (M)**: หน้าภาพรวม, สภาพอากาศ, และฟาร์ม (รอบปลูก + กิจกรรม + ฟอร์มบันทึกปุ๋ย/ยา)
3. **Slice 3 (L)**: หน้าสินค้า & คลัง และระบบรับเข้า/ส่งออก พร้อมรองรับสต็อกอัตโนมัติระดับ A
4. **Slice 4 (L)**: หน้าการเงินและคู่ค้า พร้อมระบบ Masking ข้อมูลคนและตัวเลขเงิน
