# Front-end Blueprint: owner-mobile (ฝั่งเจ้าของฟาร์ม — มือถือ)

> **SCOPE**: `owner-mobile`  
> **เป้าหมาย**: ออกแบบและวางแผนโครงสร้าง UI ฝั่งเจ้าของฟาร์ม (Mobile-First) สำหรับระบบ ERP ฟาร์มไฮโดรโปนิกส์ (ERPOganicFarm) ให้ใช้งานง่าย รวดเร็ว เหมาะกับการจดบันทึกรายวันบนมือถือ และสอดคล้องกับ 4 โมดูลหลักของ ERP (สินค้า, คลัง, รับเข้า, ส่งออก)

---

## 1. สรุปผู้บริหาร (Executive Summary)

- **ปัญหาหลักของระบบ As-Is**: หน้าจอเดิมมีความซ้ำซ้อน เมนูรก และไม่ตอบโจทย์การใช้งานผ่านมือถือในโรงเรือน เจ้าของฟาร์มต้องการระบบที่เปิดมาเจอ "งานวันนี้", "สภาพอากาศ", "สถานะรอบปลูก" และสามารถบันทึกรับเข้า/ส่งออก/ใส่ปุ๋ยได้ในไม่กี่คลิก
- **โครงใหม่ใน 1 ภาพ**: 
  - **แถบเมนูล่างมือถือ (5 ช่องหลัก)**: `[ ภาพรวม ] [ ฟาร์ม ] [ รับเข้า/ส่งออก ] [ สินค้า & คลัง ] [ การเงิน ]`
  - **เมนูรอง / ตั้งค่า**: เข้าถึงผ่านไอคอนโปรไฟล์หรือเมนูมุมขวาบน (สภาพอากาศ, คู่ค้า, ตั้งค่าระบบ)
- **5 เรื่องที่ต้องตัดสินใจก่อนลงมือทำ**:
  1. การยืนยันสัญญารายปีและพื้นที่ส่งมอบในออเดอร์ส่งออก (Phase 2)
  2. การผูกสต็อกอัตโนมัติ (StockMovement) กับทุกกิจกรรมรับเข้า/ส่งออก/ให้ปุ๋ย (D4)
  3. รูปแบบการกรอกข้อมูลการเงินในหน้ากิจกรรม (Task) แบบไม่บังคับ (D5)
  4. การใช้เว็บ PWA (Progressive Web App) เทียบกับการพัฒนาแอป Flutter แยกต่างหาก
  5. การจัดการข้อมูลลับ (D2, D3) เช่น ชื่อปุ๋ยและข้อมูลคนงาน/ลูกค้า

## 2. ส่วน 1 — แผนที่ front ปัจจุบัน (As-Is Analysis)

### 2.1 จำนวน Entry Point และความสัมพันธ์
- **As-Is**: ปัจจุบันมี Web Frontend (React/Vite) เป็น Single Page Application (SPA) ทำงานร่วมกับ FastAPI backend และ SQLite ผ่าน REST API และ JWT Authentication โดยมีมุมมอง role ทั้ง `owner` และ `developer` ในโค้ดชุดเดียวกัน และกำลังเพิ่ม Flutter Mobile App เป็น client เพิ่มเติมใน Phase 4
- **ความสัมพันธ์**: Mobile App (Flutter) และ Web Frontend ใช้ Backend API ตัวเดียวกัน โดย Mobile App เน้น UI แบบ Touch-friendly และ Compact Cards สำหรับเจ้าของฟาร์ม

### 2.2 ตาราง Route ทั้งหมด (As-Is)
| Path As-Is | Component / ไฟล์ | สถานะ API | เมนูเดิมที่ชี้มา |
|---|---|---|---|
| `/login` | `Login.jsx` | มี API จริง (`/auth/login`) | Entry point เมื่อยังไม่ login |
| `/dashboard` | `Dashboard.jsx` | ผสม (มี mock และ API จริงบางส่วน) | Sidebar / Navbar |
| `/crop-cycles` | `CropCycles.jsx` | มี API จริง (`/crop-cycles`) | Sidebar |
| `/inventory` | `Inventory.jsx` | มี API จริง (`/tables`, `/batches`, etc.) | Sidebar |
| `/sales` | `Sales.jsx` | ผสม | Sidebar |
| `/tasks` | `Tasks.jsx` | มี API จริง (`/tasks`) | Sidebar |
| `/weather` | `Weather.jsx` | มี API จริง (`/weather/*`) | Sidebar |
| `/customers` | `Customers.jsx` | มี API จริง | Sidebar |

### 2.3 Shared Components
- `DashboardLayout`, `Sidebar`, `Navbar`, `DataTable`, `Modal`, `Toast`, `AutocompleteInput`, `TaskWidget`, `WeatherWidget`, `CustomerPanel`, Chart Wrappers.
- **การนำกลับมาใช้**: มีการแยกชิ้นส่วนค่อนข้างดี แต่บางหน้ายังมีการเขียนฟอร์มซ้ำซ้อน (เช่น ฟอร์มสร้างออเดอร์กับฟอร์มรับเข้า)

### 2.4 สถานะ Responsive / มือถือ
- โค้ด Web เดิมออกแบบสำหรับเดสก์ท็อปเป็นหลัก บนหน้าจอแคบ (< 400px) Sidebar จะบังคับซ่อนแต่การจัดวางตารางยังล้นแนวนอน (Horizontal Scroll) ปุ่มและพื้นที่แตะบางจุดเล็กกว่า 44px
- **Mobile-First Solution**: สำหรับ `owner-mobile` ออกแบบให้ตารางกว้างเปลี่ยนเป็น Card List, ใช้ชิปเลื่อนแนวนอนสำหรับตัวกรอง, และใช้ Bottom Navigation Bar 5 ช่อง

### 2.5 Role และ Masking
- ระบบรองรับ JWT พร้อม role (`owner` และ `developer`).
- ฝั่ง `owner` เห็นข้อมูลจริงทั้งหมด ส่วน `developer` จะเห็นข้อมูลชื่อลูกค้า, contact, ยอดรายได้ ถูก masked เป็น ciphertext/placeholder (`████`) ตามข้อกำหนด D2/D3.

## 3. ส่วน 2 — แผนที่เป้าหมาย (To-Be) รายหน้า (`owner-mobile`)

### 3.1 ภาพรวม (Dashboard)
- **เป้าหมาย**: สรุปสถานการณ์ฟาร์มรายวันให้เจ้าของฟาร์มเห็นจบในหน้าจอเดียว
- **Wireframe ASCII (Mobile)**:
  ```
  +----------------------------------+
  + 🌿 ERP Organic Farm    [Owner]   +
  + สวัสดี, เจ้าของฟาร์ม               +
  +----------------------------------+
  + [ อากาศในโรงเรือน ]                +
  + 31.5°C | ☀️ แดดจัด | ความชื้น 65%   +
  +----------------------------------+
  + [ งานวันนี้ (2) ] [ รอบปลูก (3) ]   +
  + - เช็ค EC/pH ใน Table A1         +
  + - เติมปุ๋ยถัง B                   +
  +----------------------------------+
  + [ สรุปการเงินย่อ ]                +
  + รายได้เดือนนี้: ฿251,500          +
  +----------------------------------+
  ```
- **แหล่งข้อมูล**: มี API จริง (`/tasks`, `/crop-cycles`, `/weather/forecast`, `/customers` สำหรับรายได้)
- **สถานะ UI / ขนาดงาน**: S (≤ ครึ่งวัน)

### 3.2 ฟาร์ม (Farm: โต๊ะปลูก/รอบปลูก + กิจกรรม)
- **เป้าหมาย**: จัดการรอบปลูก บันทึกการเจริญเติบโต และบันทึกกิจกรรมประจำวันพร้อมค่าใช้จ่าย (D5)
- **แหล่งข้อมูล**: มี API จริง (`/crop-cycles`, `/tasks`, `/crop-cycles/{id}/input-applications`)
- **ขนาดงาน**: M (1–2 วัน)

### 3.3 รับเข้า / ส่งออก (Inbound / Outbound)
- **เป้าหมาย**: บันทึกการรับเข้าปุ๋ย/ยา/เมล็ด และการส่งออกผลผลิต พร้อมตัด/เพิ่มสต็อกอัตโนมัติ (D4)
- **แหล่งข้อมูล**: มี API จริงบางส่วน / ต้องเชื่อมต่อ backend สำหรับสต็อกอัตโนมัติ (Phase 2)
- **ขนาดงาน**: L (> 2 วัน)

### 3.4 สินค้า & คลัง (Inventory & Stock)
- **เป้าหมาย**: ตารางเดียวรวมสินค้าและยอดคงเหลือ พร้อมตัวกรองประเภทและแผงประวัติ Movement (D4)
- **แหล่งข้อมูล**: มี API จริงอิงตารางสินค้า/คลัง
- **ขนาดงาน**: L (> 2 วัน)

### 3.5 การเงิน (Finance)
- **เป้าหมาย**: สรุปต้นทุน, รายได้, กำไร, ค่าแรง และรายงานตามฤดูกาล/ไตรมาส
- **แหล่งข้อมูล**: คำนวณจากรับเข้า/ส่งออก/กิจกรรม (ต้องสร้าง backend เพิ่มใน Phase 2)
- **ขนาดงาน**: L (> 2 วัน)

## 5. ส่วน 4 — ช่องว่างและสิ่งที่ขาด (Gap Analysis)

| ความต้องการ (D1-D5 / 4 โมดูล) | โครงใหม่รองรับ? | สถานะ | สิ่งที่ขาด / ต้องทำเพิ่ม |
|---|---|---|---|
| D1: เจ้าของใช้มือถือ (Mobile-first) | รองรับผ่าน Flutter App & Mobile Layout | ครอบคลุม | ปรับแต่ง Touch target และ Bottom Nav |
| D2: ปิดบังข้อมูลคนทั้งหมด | รองรับผ่าน `is_masked` flag | ครอบคลุม | ตรวจสอบ Dialogs/Toasts ทุกจุด |
| D3: ปิดบังชื่อปุ๋ย/ยา/ปุ๋ยผสม | รองรับผ่าน backend/frontend masking | ครอบคลุมบางส่วน | พัฒนาหน้าจัดการสินค้าลับ |
| D4: สต็อกอัตโนมัติทุกจุด | รองรับผ่าน StockMovement | ยังไม่มี (Phase 2) | ออกแบบตาราง Movement และ API ตัดสต็อก |
| D5: กิจกรรม + การเงินไม่บังคับ | รองรับผ่านฟอร์มพับได้ | ยังไม่มี (Phase 2) | เพิ่มฟीลดค่าใช้จ่ายใน Task form |

## 6. ส่วน 5 — แผนลงมือ (Implementation Slices)

1. **Slice 1 (S)**: โครงเมนูและ Bottom Navigation Bar บนมือถือ พร้อมระบบ Routing และ Redirect จากเส้นทางเดิม
2. **Slice 2 (M)**: หน้าภาพรวม, สภาพอากาศ, และฟาร์ม (รอบปลูก + กิจกรรม) เชื่อมต่อ API จริงที่มีอยู่
3. **Slice 3 (L)**: หน้าสินค้า & คลัง และระบบรับเข้า/ส่งออก (พร้อมรองรับสต็อกอัตโนมัติระดับ A)
4. **Slice 4 (L)**: หน้าการเงินและรายงานสรุปตามไตรมาส/ฤดูกาล
